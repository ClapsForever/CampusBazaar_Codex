# 找货业务策略

## 当前实现

`src/agent/policy.ts` 定义固定业务意图、模型计划 schema、条件合并及工具白名单。`src/agent/service.ts` 负责执行每轮工作流，`src/tools/index.ts` 在执行时再次检查意图、参数与商品 ID 范围。

1. 明确的交易代办、外校查询、无关话题或助手说明先由服务端处理。否定表达和交易相关书籍主题不会仅因出现“付款”“联系卖家”而被判为代办操作。
2. 其余请求由无工具权限的模型输出 JSON 计划。计划只包含意图、条件增量、商品位置和页码；不能包含用户身份、学校身份、任意工具名或商品 ID。schema 不合法、非 JSON 或模型提出工具调用时，转为澄清，不执行查询。
3. 服务端合并条件增量，保留未提及的条件。价格修改需有本轮金额依据，明确数字优先于模型建议；清除硬条件需有相应取消要求。品类切换清除旧品类条件。价格范围矛盾、指代越界或比较范围超过调用预算时先澄清。
4. 服务端按照意图执行固定读取：搜索/补充条件只搜索，详情/比较只读取选定商品，偏好意图只读取当前用户偏好。工具使用服务端筛选条件，不采用模型提出的覆盖条件。先校验完整比较范围，再执行，避免半途截断造成商品对应关系错误。
5. 本轮结果保存在本轮局部变量中；不从消息历史提取推荐。展示商品后更新展示顺序；无结果清空顺序。详情/比较每次重新检查后端可见性和商品状态。
6. 表述模型只读取本轮问题、意图、条件和查询结果，没有工具权限，也不读取原始对话历史；问题和商品内容仅为数据，不能改变权限。拒绝、说明、澄清和无结果使用固定文案；异常工具请求使用固定结果表述替代。

会话保存 `filters`、`displayedListingIds` 和 `searchPage`。明确但不完整的找货需求（例如“找教材，预算50元”）可先保存待补充条件；无关请求、交易拒绝、无效计划和查询失败不污染状态。已有消息历史保留用于会话记录，不作为授权、条件或指代的来源。

2026-10-12 修复增加 `intent/constraints.ts`：金额单独解析，不采用类别解析器的金额遗漏；条件取消、明确成色和校区偏好依据用户原文校验。有效计划中已知预算的明确减额可由服务端计算，非法计划仍直接澄清。翻页使用明确页码和经过校验的计划页码；排序与排除在真实业务查询中执行。会话另保存最新展示标题 `displayedProducts`，给规划阶段提供名称与顺序，不提供商品描述中的指令。详情仍只接受本次展示位置并重新核验商品。

真实 API 与 Mock 使用最低成色语义；价格排序先对所有匹配商品排序再分页。用途推断限定为实现中的常见关系，排除条件为关键词匹配。最终真实模型评测结果见[修复验收报告](../../../docs/agent-paraphrase-fix-2026-10-12.md)。

## 兼容与限制

公共响应字段与状态枚举保持兼容；范围拒绝返回 `completed`、固定文案、空推荐。App 历史对话中已有的卡片仍保留，新拒绝回复不追加旧卡片。

学校权限仍由业务 API 执行，不由模型决定。没有新增交易、支付、文件、终端或任意网络工具，也没有将业务品类缩减为三个。

两个模型阶段共用本轮超时，服务端后端读取仍受工具调用预算限制。通常为一次计划模型调用及一次表述调用；无结果、澄清和固定拒绝不需要表述模型调用。

这是第一阶段的安全和专一性改动。真实模型的语义分类及自由文本表述仍可能出错；本阶段没有实施请求限流、会话容量管理或完整的回复事实校验。

## 验证

运行 `npm test`、`npm run typecheck` 和 `npm run build`。

自动测试使用 Mock 或受控模型响应，检查工具实际调用、查询条件、响应推荐和会话状态，包括：

- 找货后要求下单、讲笑话或询问助手功能：返回空推荐，不调用商品工具，不改变条件。
- 两件键盘缩小预算后只剩一件，再问“第一个”：重新读取最新展示的商品。
- 比较第二和第三件后再问“第一个”：按比较结果的新展示顺序读取。
- 空结果、下架或后端失败：不重放历史商品；错误不提交新条件。
- 预算继承、明确金额覆盖、取消条件及品类切换。
- 非法计划、额外身份字段、超范围商品位置、不允许的工具参数以及模型未经请求放宽预算。
- 模型响应发出工具调用：无执行循环，也不会调用后端工具。

真实 DeepSeek 联调需另外验证自然语言意图和比较内容；不要把 Mock 测试通过视为真实模型分类准确率的证明。
