# 邮箱自助注册与协议草案

源码更新日期：2026-10-18。此记录描述本次本地改动，不表示共享服务器已完成部署。

## 使用流程

启动页点击登录按钮下的“没有账号？立即注册”，填写邮箱、6–64 位且非全空白的密码和确认密码；注册表单可通过“已有账号？返回登录”切回。顶部仅显示当前表单标题，不重复放置切换按钮。图形验证码本轮暂时移除，当前界面不获取验证码，注册接口不要求或校验验证码。表单失败保留邮箱和密码，不自动重复注册。

协议选项默认不勾选；用户可在提交前阅读用户协议、隐私政策及社区与交易规则。主动同意后注册，API 在同一事务中创建账号、记录协议版本和同意时间并签发会话，成功后自动登录并进入首页。新用户默认使用随机昵称，可在个人设置中修改。服务端继续执行注册来源 IP 限流及邮箱唯一性校验。

测试阶段允许任意邮箱，不验证邮箱归属，也没有学生身份验证；系统学校范围由后端配置决定。邮件找回密码、注销、数据删除及保存期限不在本轮实现范围。运营主体和联系邮箱尚未确定，文档保留待填标记。

安装业务 API 锁定的依赖后，从仓库根目录执行：

```sh
node --test scripts/ui-regression.cjs scripts/registration-regression.cjs
node scripts/ui-api-regression.cjs
```

本轮需验证无验证码字段的完整注册流程、注册期间无验证码请求、默认未勾选、重复提交、并发邮箱唯一性、IP 限流、协议版本与记录原子性、重启与数据库迁移，以及原有登录、商品、交易、消息和 AI 历史契约。测试使用临时数据库、本机随机端口或替身，不调用真实模型；具体通过结果以本轮实际运行记录为准。

本轮实际结果：40 项前端逻辑测试、21 项 API/业务契约测试及 1 项真实前端注册链路测试通过。真实链路执行实际 ArkTS ViewModel 和认证服务，对隔离的 HTTP API 与 SQLite 完成无验证码注册（201）、读取用户（200）、退出并验证旧令牌失效（401）、重复邮箱（409）、重新登录（201）和商品列表读取（200）；注册及切换表单均无验证码请求。ArkTS、资源和未签名 HAP 构建通过，三份离线法律文档与 Markdown 正文及 `2026-10-18-draft-2` 版本同步检查通过。

## 历史故障与部署前提（2026-10-18）

此前从运行中的鸿蒙模拟器直接向 `http://101.35.53.59:18080/api/v1/auth/captchas` 发送匿名 `POST`、JSON `{}`，实际收到 HTTP 401：`code: UNAUTHORIZED`，提示“需要有效的 Bearer 令牌”。这是旧 API 未开放匿名验证码路由的历史排查结果；当前客户端已移除验证码控件和请求，不再以获取验证码作为注册前提。

**移除验证码本身不会更新远端旧 API。** 当前邮箱注册仍需匿名 `POST /api/v1/auth/registrations`，必须部署配套新版 API 后才能在该实例完成注册，不能要求未注册用户先提供登录令牌。现有本机 SSH 身份登录测试服务器被拒绝，本轮尚未据此更新远端服务。更新后须验证匿名注册返回 201、协议版本与同意记录、自动登录及重复邮箱处理；远端部署状态以实际验收为准。

## 模拟器或真机验收

1. 同时运行新版 API 和新版 App，切换登录/注册；查看三份文档后返回，确认邮箱、密码和确认密码输入保留，协议未自动勾选，界面无验证码控件，切换及提交不发验证码请求。
2. 确认密码不一致、未勾选协议、已注册邮箱和触发限流均应显示错误，并可修正或按提示重试；同一次提交不会重复创建账号。
3. 使用新邮箱注册并自动进入首页，退出后以同一邮箱密码登录；在个人设置修改随机昵称。
4. 在窄屏、大字体及键盘展开时检查滚动、确认密码、协议选项与提交按钮；在“我的”打开三份文档并返回。
