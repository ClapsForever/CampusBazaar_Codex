这是小组开发测试配置。HTTP 会明文传输密码与登录令牌，只使用测试账号和测试数据，密码不要与个人常用密码相同；正式发布前恢复 HTTPS。

## 当前服务器配置

- licx Nginx 监听 18080，已删除来源 IP 的 `allow` 和 `deny all`。API 与 Agent 继续只监听服务器回环地址 18081、3300。
- 保留邮箱密码验证、会话鉴权、资源归属检查、登录限流、图片签名、内部接口屏蔽和 AI 并发限制。旧验证码入口继续关闭。
- API 的 `PUBLIC_BASE_URL` 和前端地址均为 `http://101.35.53.59:18080`，商品图片与头像使用同一入口。
- 用户已在腾讯云控制台确认：TCP 18080、来源 `0.0.0.0/0`、允许；保留其他原有规则。
- 队友的 80 端口、API、Agent 和数据不参与此次修改。现有域名 HTTPS 服务保留，当前 App 不依赖它。

实际部署配置为 [`deploy/ubuntu/licx-ip-test/nginx.conf`](../deploy/ubuntu/licx-ip-test/nginx.conf)，仅用于 licx 的独立用户 Nginx，不能替换队友的 80 端口配置。服务器与仓库文件 SHA-256 均为 `d7a0e54b3f2e5131effc529354438fcd9f66905d8cd6f84f6930290f8a710a8a`。

公网验收同时修复了旧临时目录权限问题：原 `tmp/client`、`tmp/proxy` 属于 `nobody`，licx 工作进程无法写入，较大图片会下载中断。现在使用 licx 自有、权限 700 的 `tmp/licx-client` 和 `tmp/licx-proxy`。原目录保留，无文件或目录删除。部署本配置时须先以 licx 身份创建这两个目录。

## 每位组员的操作

1. 在 `CampusBazaar_Codex` 仓库执行 `git pull`。
2. 确认 `entry/src/main/ets/service/BackendRuntimeConfig.ets` 中的 `BUSINESS_API_BASE_URL` 为 `http://101.35.53.59:18080`。
3. 在电脑或模拟器浏览器打开 `http://101.35.53.59:18080/health/ready`，应返回 `{"status":"ok"}`。
4. 在 DevEco Studio 中构建、签名并运行 App，使用项目组分配的邮箱密码登录。已安装包若本来就使用此 IP 和端口，可直接重试；旧域名包需要重新安装，单独改服务器不能改变其地址。

不需要 SSH 隧道、修改模拟器 hosts 或登记公网 IP。切换校园网、家庭网络或手机热点后，继续使用同一入口。

## 连接排查

- 连接超时：核对腾讯云 TCP 18080 的全部 IPv4 入站规则和本机代理。Mac 可执行 `curl --noproxy '*' --max-time 15 http://101.35.53.59:18080/health/ready`；Windows 用 `curl.exe --noproxy "*" --max-time 15 http://101.35.53.59:18080/health/ready`。
- 健康检查成功、App 仍连接失败：确认安装的是本仓库使用 IP:18080 的新包，再检查模拟器网络及代理。
- 登录 401 或邮箱密码错误：连接已到 API，核对本实例的预置账号。队友实例账号和旧验证码不能直接用于这里。
- 当前入口不再按 IP 返回 403；业务操作的 403 可能属于资源归属或角色权限，应结合接口错误文字判断。
- 匿名访问业务资料返回 401、访问内部路径返回 404 属于预期。根路径不是登录网页，不能据此判断账号登录失败。
