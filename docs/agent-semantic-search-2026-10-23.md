# AI 找物：需求理解与语义检索

## 问题与改动

原实现要求模型的关键词直接出现在用户原话中或命中少量固定同义词，后端又对单一关键词做文本匹配。用户说“线代”，模型即使生成“线性代数”也会被合并策略丢弃；“我想考六级”这样的目标无法覆盖多个备考物品类型。

现在由计划模型理解用户想解决的问题，先生成1–8个物品方向 `needs`，再生成主题 `keyword` 和1–12条 `queryTerms`。支持用途、困扰、目标、特征、简称及结合上下文的追问；不要求用户先知道商品名称或说“帮我找”。真实模型可自行推断相关词汇和物品类型，不使用固定的学科、考试或场景白名单。正式模型路径不调用 Mock 计划器，线代/六级的固定合成响应已移入测试目录。例如：

| 用户需求 | 检索范围示例 | 应返回的候选 |
| --- | --- | --- |
| 帮我找一本线代教材 | 线代、线性代数、linear algebra | 线性代数教材、线代讲义等 |
| 我想考六级 | 六级、大学英语六级、CET6、CET-6、CET 6 | 六级词汇书、真题试卷、听力与阅读资料等 |
| 我只需要六级词汇书 | 六级 词汇、六级 单词、CET6 vocabulary | 词汇相关资料，排除只有试卷内容的商品 |
| 下周要搬宿舍，有什么能用得上的 | 整理箱、打包袋、手拉车等 | 跨类别的相关用品 |
| 手机总没电，图书馆插座又远 | 移动电源、充电宝、加长充电线 | 便携充电、延长充电距离相关用品 |
| 桌上充电线缠成一团 | 理线器、绕线器、线材收纳 | 线材固定与收纳相关用品 |
| 想在宿舍锻炼 → 有没有能塞抽屉里的 | 结合已有目标查询弹力带、折叠瑜伽垫 | 更新为便于收纳的锻炼用品，保留原预算 |

空格表示一条查询中的多个词都需命中，各条查询取并集。短查询匹配商品标题、描述、类别和版本。存在 `queryTerms` 时，`keyword` 用于标记需求，不额外要求逐字命中。没有该字段的旧调用保留原检索逻辑。

## 执行与会话

- `backend/agent/src/agent/prompts.ts` 指导模型区分具体物品与目标型需求，生成同义和用途检索词；明确的商品类型不能被随意扩展成整个大类。
- `backend/agent/src/agent/policy.ts` 校验计划并合并状态，允许语义展开词；预算、校区、成色、版本和排除条件继续按用户原文校验。
- `backend/api/src/store.ts` 在同一条参数化 SQL 中对检索分支取 OR，学校、在售、交易占用等限制位于分支之外；统一排序后分页，每件商品只出现一次。无需新增数据库字段、索引服务或向量库。
- 会话保存物品方向，通过 `previousNeeds` 供模型理解模糊追问。改预算、校区、排序或翻页时沿用已有方向和检索范围；更换需求时替换或清除旧内容。详情和比较仍根据最新展示顺序读取。
- “天气”“写代码”等词也可出现在保暖和编程资料需求中，因此交给模型判断意图，不再按单个词直接拒绝。
- 回复显示“我理解你可能需要：……”和实际商品，不展示内部检索词；每页最多10件，有更多时提示“继续”。无结果也显示物品方向和有效条件。

计划和表述模型仍无工具权限。只能推荐当前查询到的真实商品；用途相关性是候选解释，不能据此保证商品考试适用性、质量或库存。

## 验证与启用

在 `backend/agent` 执行 `npm test`、`npm run build`，在 `backend/api` 执行 `npm test`。新增测试包含真实业务 HTTP + 内存 SQLite 的完整查询链路、真实模型适配器的受控 SSE 响应，以及数据库检索条件测试，覆盖：

- 线代简称命中线性代数；六级目标覆盖词汇、试卷、阅读和听力。
- 词汇类明确需求不混入试卷、四级或普通英语教材。
- 模型自行提供示例词表之外的搬宿舍检索计划，跨类别找物。
- 夜间阅读、线材整理、便携充电、出行保暖、编程入门资料等开放需求计划；模糊追问无需重复商品名。
- 多查询合并去重、全局排序和分页；后续预算、排除、校区、成色、版本和权限限制继续生效。
- 切换主题清除旧检索词；最新结果的商品顺序可继续查看详情。
- 空白、空数组、重复、过长、超量及非法 JSON 计划受校验；SQL 字符作为普通参数处理。

自动测试不调用真实 DeepSeek。当前本机没有 Agent `.env`，本次未做在线模型评测；真实模型的需求理解和检索词覆盖率仍需在配置好的测试环境联调，不能将受控测试通过视为自由输入的召回率保证。这里实现的是模型驱动的检索扩展，描述缺失、罕见别名或错误展开仍可能造成漏查或误查。

通用模糊需求在线评测：构建两个后端并配置真实模型密钥后，在 `backend/agent` 运行 `npm run eval:fuzzy`。`evals/fuzzy-needs-cases.json` 包含9类模糊需求和1个链路自检场景；不注入预设模型计划或检索词，只核对真实返回商品是否满足人工期望。评测只使用合成身份、内存 SQLite 和随机回环端口，不访问线上商品库。旧评测脚本的短信登录依赖也已改为合成身份，兼容当前 API。

本次本地验证结果：Agent 176项测试通过；业务 API 源码未在本轮追加修改，上一轮29项测试已通过。Agent 构建、`git diff --check` 和在线评测脚本的 Mock 链路自检通过。模糊需求的自动回归使用受控模型响应，验证服务端可以执行这些开放计划，不代表真实 DeepSeek 已通过9类在线需求评测。

**启用时同时构建并重启业务 API 和 Agent**；只更新 Agent 而保留旧 API 无法执行多词并集。无需修改 App 或迁移现有商品数据。本次仅修改本地源码，没有更新线上服务。
