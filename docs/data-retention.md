# 一年数据保留与到期清理

本次为源码实现和隔离测试，不代表共享服务器已经部署；没有运行真实数据清理。

## 规则与关联数据

一年定义为 365 × 24 小时。业务 API 在启动时执行一次清理，此后每小时执行一次；停止服务期间不执行，重新启动时补清理。数据库升级到 schema v7，只新增文件删除重试表和时间索引，迁移本身不删除业务数据。

| 数据 | 起算时间与处理 |
| --- | --- |
| 账号资料 | 注册/管理员创建时间 `users.created_at`；到期清除邮箱、手机号、密码摘要、验证时间、原昵称、头像，停止登录并撤销全部会话 |
| 商品 | `published_at`；到期清除标题、描述、分类、成色、校区、版本、价格等原始内容 |
| 图片及头像文件 | 上传时的 `product_images.created_at`；清除元数据、头像引用并删除对应文件，绑定商品或改作头像不重新起算 |
| 交易及消息 | 分别按 `create_time`、`send_time` 起算；到期清除相应内容 |
| AI 业务历史 | 每一轮按 `agent_turns.created_at` 分别到期，旧轮次删除不连带删除同一会话内的新轮次 |
| 协议同意、幂等记录 | 分别按 `accepted_at`、`created_at` 起算 |
| 导入的账号偏好 | 当前无独立写入入口和时间字段，与其账号原始创建时间一致 |
| 验证码、限流、登录会话 | 仍按原有较短有效期清理；不会把五分钟验证码或七天登录令牌延长至一年 |

旧父记录被未到期的子记录引用时，不级联删除新数据。先清除旧记录的原始内容，只保留维持关联所需的标识；新引用到期后删除剩余行。过期账号关联的在售商品下架、进行中交易取消，新内容仍保留至自身期限。**账号也按注册创建时间到期；持续登录或修改资料不会续期原始账号记录。**

图片元数据删除与文件重试队列在同一 SQLite 事务提交。文件被占用、权限错误或服务退出导致删除失败时，下次任务继续处理；缺失文件视作已处理。只删除上传目录内符合应用 UUID 命名规则的普通文件，拒绝符号链接和路径穿越，不递归清理任意目录。未到期孤儿文件及未知文件名不处理。

启用 SQLite `secure_delete`，清理后尝试截断 WAL；不宣称对磁盘快照、供应商副本或他人另存内容进行物理覆写。

## 配置及手动预览

`backend/api/.env` 中 `DATA_RETENTION_ENABLED=true` 为默认值。迁移或排查时可显式设置 `false` 暂停 API 的自动清理；此开关不改变手动 CLI 的明确执行指令。

先构建，在 API 目录执行：

```powershell
npm run build
npm run retention:cleanup -- --dry-run
```

默认也是预览：回滚模拟的业务数据库删除，不删除图片、备份，也不输出账号凭据。打开旧数据库可能执行 v7 的非删除式结构迁移。报告只包含表名、数量和截止时间，不输出邮箱、聊天或令牌。预览不枚举备份和孤儿文件的删除数量。

确认环境文件指向预期实例、完成数据库和图片备份后，明确执行：

```powershell
npm run retention:cleanup -- --apply
```

本次开发没有对本机已有业务数据库或共享服务器执行上述命令。自动清理的部署应先在数据副本演练，再切换正式 API；升级后不能直接用只支持 v6 的旧 API 打开 v7 数据库。

## 备份与外部副本

新版 `deploy/aliyun/data-bundle.mjs snapshot` 在新备份 manifest 中添加 `retention.kind=one-year-v1` 和到期时间。到期时间采用其中最早的原始数据时间加 365 天，复制备份不会重新计时；一个旧记录到期会使整份该备份退役，不能把备份生成时间误当成原数据上传时间。

可选配置 `RETENTION_BACKUP_DIR` 为专用备份父目录；不得包含正在运行的数据库或上传目录。任务只清理该目录内带上述标记、到期且文件清单符合快照规范的备份子目录；普通文件、未标记旧备份、未到期备份、包含符号链接或额外文件的目录均保留。文件删除中断会通过 manifest 的删除状态在下次继续处理。

历史 `.tar.gz`、旧迁移副本、其他服务器、本机下载副本、系统日志和第三方供应商记录不在该任务的删除权限内。部署负责人需另行盘点、配置相应保留策略并处理历史副本；不能因主数据库已清理就承诺这些副本已删除。供应商地域沿用运营方提供的上海/杭州信息，本次代码没有重新核验供应商合同。

Agent 的短期内存每分钟维护一次，在原有空闲有效期之外增加从会话创建起算的 365 天绝对上限，持续使用也不会无限保留同一份上下文。迟到结果不能重新保存已到绝对上限的内存会话。
