# AI 找物召回修复（2026-10-31）

> 2026-10-31 15:02 已部署至阿里云 Agent，服务器回归和线上模型评测通过，实际商品“六级资料”已检出。运行目录、验证及回退见 [部署记录](agent-rollout-2026-10-31.md)。

## 问题与复现

用户输入“我快要考六级了，想准备一下，你有什么推荐的资料吗”，已有商品仍可能无法召回。计划模型能理解备考方向，但生成的复合词会被后端连续文本匹配：“英语六级”不等于标题中的“六级”，“六级真题”也不能匹配“六级历年真题试卷”。

使用本机配置的真实模型 `deepseek-flash`、隔离 SQLite 和实际业务 HTTP 查询复现：旧代码对截图原话只返回四件预期商品中的两件，漏掉“六级资料”和“CET-6 阅读专项训练”；“想找六级真题”返回空结果。记录见 `backend/agent/evals/results/retrieval-20261031-before.json`。这些都是合成商品和身份，没有读取线上商品或写入线上账号、历史。

## 实现

- 首次计划保留目标的简称、等义别名与独立主题分支；需要同时匹配的主题和物品类型用空格拆开，例如“六级 真题”。明确只找词汇书时，每个分支仍须保留词汇子类。
- 首屏查询的总数为零时，最多增加一次模型检索修正和一次业务查询，受原工具调用次数及整轮超时限制。后续空页不触发补查，也不重置分页。
- 补查分别输出目标范围、主题别名和具体检索表达。对于泛目标，服务端把主题别名加入查询并集，避免只查细分物品而漏掉统称商品；明确商品或子类只执行对应的具体表达。
- 修正结构不允许预算、校区、版本、成色、类别、排除项或身份字段。第二次查询沿用原硬条件及可信身份。修正后的检索词保存在会话中，后续预算、排序和翻页继续使用。
- 无结果回复描述本次检索未命中；语义查询显示“需求”，避免把模型归纳的主题误写成用户指定的字面关键词。

补查初版曾在旧会话回放中漏掉“六级资料”，该失败记录保留在 `retrieval-20261031-repair.json`。最终补查改为由服务端显式合并目标主题分支，没有增加考试或商品关键词白名单。

复现最终评测：

```sh
cd backend/agent
npm run build
node scripts/evaluate-paraphrases.mjs --real --cases evals/retrieval-regression-cases.json --output evals/results/retrieval-local.json --concurrency 2
```

评测还需预先构建 `backend/api`，并私下配置模型凭据。自动回归不调用真实模型；上述在线评测单独调用真实模型。
