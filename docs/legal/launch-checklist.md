# 正式发布前边界确认清单

版本：2026-10-18-draft-2
核对日期：2026-10-18
用途：供项目负责人完成业务事实确认及上线前工作；本次注册功能开发不包含下列全部运营能力的实现，也不将此清单加入普通注册必勾项。

## 本次已确认的范围

- 先用于内部测试，接受符合格式的任意邮箱，不限制学校邮箱域名。
- 注册填写邮箱、密码和确认密码，主动同意协议后提交，成功后自动登录；图形验证码暂时移除并转为下列待办，不发邮件，不验证邮箱归属，也不视为学生或实名验证。
- 注册前可独立阅读协议、隐私政策和社区规则，主动勾选后提交；服务端保存用户协议及隐私政策版本与接受时间。
- 已有商品、图片、校区和见面地点、卖家资料、交易状态、交易内消息、个人资料与改密、AI 找货及持久化历史。
- 当前没有支付、托管、物流、身份认证、在线退款和完整的投诉申诉能力。账号注销、删除、留存和权益处理纳入发布前工作，当前不实现这些流程。
- 运营主体和联系方式尚未确定；三份文档明确为草案，版本统一为 2026-10-18-draft-2。

## 必须补齐的业务事实和能力

### 1. 运营主体、服务范围与有效联系

- [ ] 确定真实运营主体名称或姓名、地址、服务地区和生效日期，并补入用户协议与隐私政策。
- [ ] 建立实际有人负责的客服、违法/侵权举报、个人信息权益和申诉渠道，明确受理、核查、反馈、复核时限及人员权限。
- [ ] 确定从内部测试转为公开服务的标准、访问范围及测试结束数据处置；不得因称为测试就省略实际需要的保护。
- [ ] 根据真实业务主体、用户发布交易模式及开放范围，核对市场主体、App/网站备案、许可和校园使用授权等适用要求；不得杜撰备案号、学校背书或经营资质。

### 2. 年龄、身份、邮箱与账号恢复

- [ ] 决定年龄范围及相应执行措施；如涉及不满十四周岁用户，先完成适用的监护人同意和专门个人信息规则。
- [ ] 决定正式版是否验证邮箱或限制域名，明确邮箱误填、被占用、修改与找回账号流程。图形验证码不补足身份核验。
- [ ] 核对公开交易场景依法需要的发布者身份、联系信息核验及真实身份信息要求；“不接入支付”本身不能证明无需核验，不因内部学校分组就宣传学生认证。
- [ ] 确认是否有高校授权或实际身份核验，未经确认不展示“校方认证”“学籍已认证”等标签。

### 3. 图形验证码恢复（待办，当前未启用）

- [ ] 在服务端恢复四字符图片验证码生成和校验，并提供点击刷新；同步 App 控件及注册请求字段。
- [ ] 验证刷新旧题失效、到期、来源 IP 绑定、每题单次校验、失败消费、获取与注册限流及错误提示；防止重放和并发重复使用。
- [ ] 在真实部署环境验证匿名获取接口、刷新、过期和完整注册流程，确认无须先登录，验证重复邮箱及网络失败可重试；本机测试不能替代实际部署验收。
- [ ] 恢复前同步协议与隐私政策版本、数据处理告知、历史记录和新记录的清理规则，完成必要的重新告知安排。

### 4. 权益、注销、删除与留存

- [ ] 实现或建立实际可用的查阅/复制、必要更正、删除、限制处理、撤回同意、账号注销及符合条件的转移申请流程；明确最小必要的身份核验，不能要求用户提供密码。
- [ ] 分别确定账号与资料、商品与图片、交易与消息、AI 历史、历史验证码记录与当前限流、登录会话、同意记录、幂等记录、日志和备份的期限、起算点、到期处理、例外和负责人。
- [ ] 设计注销对商品、交易双方历史、消息、头像、上传原图、AI 历史与备份的影响；合理平衡他人交易凭证及法定留存义务，避免“注销立即删全部”或“任何数据永久保留”两种不准确承诺。
- [ ] 如业务适用《电子商务法》第三十一条，商品服务与交易信息自交易完成之日起的法定最低留存要求应落实到具体对象；不将其扩大为所有照片、AI 问题和安全日志的统一保存期限。
- [ ] 完成旧头像、未发布图片、过期会话/限流和业务重试记录的清理；验证到期、备份恢复、删除请求如何执行，不能只把过期字段当作物理删除。

### 5. 第三方、AI 与处理地域

- [ ] 列明实际云服务器、备份、代理/网络、安全或运维服务及模型供应商的法律主体、联系方式、隐私规则链接、处理数据种类、目的、方式、地域和留存。
- [ ] 核实 DeepSeek 或实际模型服务的采购条款、受托/独立处理关系、是否用于训练、保留多久、删除与退出机制，以及供应商是否再委托。未核实前不写“零留存”“绝不训练”“无跨境”。
- [ ] 根据实际数据流落实受托处理协议、监督、影响评估、必要的单独同意及适用跨境要求；普通注册勾选不能兜底所有第三方提供或公开处理。
- [ ] AI 调用前清楚提示将发送的问题、必要商品文字及图片访问链接；保留不使用 AI 仍可普通搜索的选择。核对问题、卖家昵称和见面地点中可能包含的个人信息风险，评估模型是否需要可直接读取图片的链接。
- [ ] 核实模型/应用的生成式 AI 备案或登记、安全评估和已备案模型信息公示等适用要求，不默认接入已备案模型即完成本应用全部手续。
- [ ] 完成适用的 AI 显式标识、隐式标识以及复制、导出、转发场景；在用户协议中写明最终样式和方法，验证生成回复、商品数据和用户上传内容的区分。

### 6. 发布、交易和治理

- [ ] 确认正式允许交易的品类、禁售和受限范围、处理负责人；高风险或资质要求品类在未有相应保障时不开放。
- [ ] 完善错误商品、违法/侵权内容的处理与停止传播能力，以及投诉、知识产权通知/反通知、申诉及必要记录制度；清单中的规则不表示代码已具备执行能力。
- [ ] 明确当前卖家单方“完成交易”的含义及误操作处理，不将其当作买家验收或支付核验；决定正式是否需要买家取消、双向确认、争议与退款协调能力。
- [ ] 按实际业务评估经营者识别、权益保障、信用评价和交易信息公示等适用义务；不以“个人二手”一概排除消费者法定权利。
- [ ] 适用电子商务平台规则时，建立协议与规则修改征求意见、至少提前七日公示等相应流程，并提供便利查阅、保存方式。

### 7. 传输与图片安全

- [ ] 正式服务启用有效 HTTPS，验证 App、业务 API、图片地址和代理入口，关闭不必要明文入口；当前共享测试 HTTP 不能据文档视为安全传输。
- [ ] 明确商品与头像签名链接当前二十四小时内可转发读取的范围，决定是否需要缩短期限、改为认证读取及撤销访问机制。
- [ ] 完成上传照片 EXIF 去除或合适的最小化处理，提醒避免人脸、证件和详细位置；注意移除 EXIF 仍不能消除画面中的个人信息。
- [ ] 建立最小权限、服务密钥管理、备份恢复、日志脱敏与轮转、安全事件负责人和通知预案；以实际核验结果更新隐私政策，不写“全程加密”“绝对安全”。

## 代码核对依据

以下为 2026-10-18 对当前工作区源码的核对线索，修改实现后须同步复核：

- `backend/api/src/db.ts`：账号、会话、商品、图片、交易、消息、幂等记录、用户偏好、AI 历史及注册同意数据表。
- `backend/api/src/store.ts`、`registration.ts`、`password.ts`、`server.ts`：注册与会话、限流、密码摘要、已停用的图形验证码实现、图片签名、交易权限和状态、文字消息、历史持久化、上传原图及访问日志。
- `entry/src/main/module.json5`、`entry/src/main/ets/service/BusinessApiClient.ets`、`entry/src/main/ets/service/AuthenticationService.ets`：仅声明网络权限、运行内存令牌、注册版本字段及客户端认证行为。
- `entry/src/main/ets/viewmodel/PublishViewModel.ets`、`ProfileViewModel.ets`、`service/ImageUpload.ets`：系统拍照/图库、见面地点拼入商品描述、上传文件未去 EXIF。
- `backend/agent/src/agent/service.ts`、`tools/index.ts`、`contracts/index.ts`、`config/index.ts`、`sessions/store.ts`：两阶段模型输入、只读工具与偏好、商品文字视图、默认 DeepSeek 配置和内存续聊状态。
- `entry/src/main/ets/service/BackendRuntimeConfig.ets`、`deploy/ubuntu/*`：共享测试入口、部署模板、日志与备份说明；模板不替代实际运行环境核实。

## 拟稿采用的官方来源

核查日期：2026-10-18。以下用于支持条款设计与发布前任务；未将全部义务一概认定适用于尚未确定的运营模式，也未用法规文本补造当前代码能力。

1. [《中华人民共和国个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)：第十三至十九条（处理依据、告知、同意和期限），第二十一至二十五条（委托、提供、公开和自动化决策），第二十八至三十一条（敏感信息与儿童），第三十八至三十九条（跨境），第四十四至五十条（权利），第五十一、五十五至五十七条（措施、评估和事件）。
2. [《中华人民共和国民法典》](https://www.court.gov.cn/zixun/xiangqing/233181.html)：民事行为能力、合同成立与履行、格式条款提示和效力、依法不得免除的责任及人格权益保护。
3. [《中华人民共和国电子商务法》](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3e75434c954b4cb9bd14867dacff26d1.html)：第二条、第九条（业务定义），第二十四、二十七、三十一至三十四条（退出、身份、留存、公示和变更），第五十九至六十二条（投诉和争议协助）。实际业务符合定义时应据实评估，不以“无在线支付”自动排除。
4. [《网络数据安全管理条例》](https://app.www.gov.cn/govdata/gov/202409/30/520076/article.html)：第九至十二条（安全、事件及受托/提供记录），第二十一至二十五条（公开规则、期限、权利、注销及转移）。
5. [《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)：第二条（适用范围），第九至十五条（服务及输入记录保护、投诉），第十七条（特定服务的安全评估和备案）。
6. [《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)：适用范围、显式/隐式标识、服务协议中的标识规范及传播要求；2025-09-01 起施行。
7. [国家网信办生成式人工智能服务已备案信息公告](https://www.cac.gov.cn/2024-04/02/c_1713729983803145.htm)：已上线 AI 应用或功能对使用的已备案服务情况、模型名称及备案号的公示要求；实际模型信息应重新核实，不能复制示例编号。

本清单是项目实施与事实确认工具，不是“全部适用合规事项均已完成”的结论。公开运营前应结合最终产品、实际部署和真实主体完成复核。
