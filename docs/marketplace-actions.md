# 商品管理、取消交易、普通筛选与手动删除 AI 历史

本次在 main 单独实现四项功能，参考 PR #2 的接口和交互，不合入该 PR 的提交，也不引入每账号最多保留十段对话的自动清理策略。

- 商品详情与“我发布的”提供下架入口，操作需确认。只有卖家可下架自己的在售商品；有待确认、待交易订单时先处理订单。下架后商品不出现在可购买列表和 AI 查询中，保留照片、商品及历史交易引用。
- 买卖双方均可取消待确认、待交易订单。取消需确认，商品重新可购买，已结束订单不能继续发送消息；卖家原有接受、拒绝、完成操作保留。
- 普通搜索可组合关键词与多选价格区间、大类、校区，同维度取并集、不同维度取交集，支持仅选条件搜索和清除筛选。价格接口单位为分，区间左闭右开，最高档为 300 元及以上；大类兼容已有小类数据。
- AI 历史列表和详情提供整段删除入口，需确认，只允许本人操作。服务端删除会话与全部轮次，App 删除当前会话时清空当前对话。保留现有分页，不因历史数量增加而自动删除旧对话。在途续聊结果不得重新创建已删除会话。

数据库增加 `DELISTED` 商品状态和 `CANCELLED` 交易状态。升级重建相关状态约束并验证外键，保留账号、会话、图片、商品、交易、消息和 AI 历史。与注册分支整合后的最终 schema 版本和升级路径以 API 文档为准；更新服务前备份数据库和 uploads，回滚需使用匹配的程序与数据库。

验证覆盖 API 权限与状态机、多条件组合、手动删除与历史超过十段的保留、请求竞争，以及既有前端逻辑与业务契约。
